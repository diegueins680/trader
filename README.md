- `--open-threshold 0.002` (or legacy `--threshold`) entry/open direction threshold (fractional deadband)
  - Live bots now resume closed-trade performance memory from the latest saved bot snapshot when the symbol, market, interval, and method still match. That means rolling expectancy/win-rate/profit-factor gates, adaptive filter tightening, loss-streak tracking, and the first post-restart decision continue from prior wins and losses instead of restarting from an empty session.
  - Entries must also clear that deadband with at least `1.5x` edge headroom; forecasts that only barely cross the threshold are held as `HOLD (EDGE_HEADROOM)` instead of opening on a boundary-touching move.
  - Entries are also vetoed when the method-selected absolute edge does not clear the active headroom requirement plus an explicit round-trip fee floor (`2 * fee`), which blocks low-margin trades that only look profitable before fees. The fee floor must be finite and non-negative; negative or non-finite fee inputs and missing or non-finite edge samples fail closed.
  - Entries are also suppressed when the method-selected absolute edge exceeds the tighter of the credible-edge ceiling and `4x` the active open-threshold; exact equality at that cap remains admissible, and non-finite threshold or edge inputs fail closed instead of bypassing the spike veto.
  - The live `Trader.SignalGates` path now applies the real 24-bar directionality gate instead of the old compatibility shim. Fresh-entry directionality first requires the 24-bar efficiency sample to be finite and within `[0,1]`; missing directionality snapshots plus `NaN`, negative, or above-1 efficiency values are vetoed conservatively instead of being treated as strong-band directional evidence. Entries are now also vetoed as `NON_DIRECTIONAL_CHOP` when 24-bar price efficiency is `<= 0.25`, and as `NON_DIRECTIONAL_MR` when efficiency stays `<= 0.40` while saved HMM regime probabilities are clearly mean-reversion-dominated (using the existing `--regime-bank-hysteresis` gap). In that same weak-directionality review band, `--regime-bank-hysteresis` itself must be finite and non-negative; negative or non-finite values now fail closed as `NON_DIRECTIONAL_MALFORMED` instead of being normalized into a looser MR comparison. In that same weak-directionality review band, fresh long and short entries now share one signed additive-path confirmation rule: the requested side is admissible only when the signed weak-band `zScore` is finite and at least `0.75` (equivalently `zScore >= 0.75` for longs and `zScore <= -0.75` for shorts). Exact equality at the signed boundary remains admissible, while opposite-signed, zero, missing, or non-finite weak-band scores fail closed for the requested side. Saved HMM regime probabilities still fail closed as `NON_DIRECTIONAL_MALFORMED` when any component is missing, non-finite, outside `[0,1]`, or when the three-probability mass is non-positive or drifts by more than `1e-3` from `1`.
  - Directionality efficiency and z-score are derived from the additive per-bar return path, so clean monotonic trend windows remain directional instead of being misclassified as malformed when the compounded endpoint return slightly exceeds the summed simple-return path.
  - `haskell/scripts/review_bot_day.py` now emits additive cutoff observability in both JSON and markdown: interval-aware stale-snapshot diagnostics (`latestSnapshotAgeMs`, per-symbol cutoff freshness rows, `staleSnapshotsAtCutoff`) plus a compact latest pre-cutoff `latestSignal.action` census so zero-trade review windows still show stale snapshots and dominant HOLD reasons.
  - `haskell/scripts/review_bot_day.py` also keeps low-directionality review accounting aligned with the live gate: same-day order flow is partitioned as `entry_or_add` versus `exit_or_flatten`, `nonDirectionalOrderAttempts` counts only entry/add flow, weak-band entry/add reviews use the same signed additive-path zScore rule as live (`zScore >= 0.75` for longs, `zScore <= -0.75` for shorts), and carry-management exits from existing or adopted positions stay in the separate `nonDirectionalExitOrFlattenEvents` / `nonDirectionalUnknownRoleEvents` review buckets.
  - Ops persistence now defaults high-volume Binance REST request audit rows (`binance.request`) off, persists `bot.status` ops snapshots every 5 minutes by default, and supports `TRADER_OPS_DISABLED_KINDS` plus `TRADER_BINANCE_REQUEST_OPS_ENABLED` / `TRADER_BOT_STATUS_LOG_INTERVAL_MS` for production disk-growth control.
  - Fly Postgres disk monitoring is available with `npm run monitor:fly-postgres-disk -- --app tdf-hq-db --warn 75 --critical 85`; set `TRADER_DISK_ALERT_WEBHOOK_URL` to post warning/critical JSON alerts from cron, GitHub Actions, or another scheduler.

## Autoloop
- The repo autoloop now treats merged local branches that are still attached to Git worktrees as prune skips instead of blocking the forever runner before any bounded repair cycle starts.
- The forever runner now prunes stale `git worktree` metadata before merged-ref cleanup, and it saves failed dirty-cycle snapshots onto dedicated `autoloop/recovery/*` or `autoloop/checkpoint/*` branches instead of writing those `WIP` rescue commits directly onto `main`.
- The bounded autoloop now includes `hlint app test bench` in its safe verification set and can apply direct `Found:` to `Perhaps:` HLint replacements for editable Haskell files when CI fails on simple HLint-only suggestions.
- The GitHub-hosted autoloop now requires `AUTOLOOP_PUSH_TOKEN`; it no longer falls back to `github.token`, and it no longer skips post-push CI waiting. That keeps Actions polling and failed-log ingestion mandatory after each autoloop push.
- The GitHub-hosted autoloop now installs a pinned prebuilt `fourmolu` release binary instead of compiling `fourmolu` from source on every run, which removes a slow bootstrap step before the bounded loop can start.
