- `--open-threshold 0.002` (or legacy `--threshold`) entry/open direction threshold (fractional deadband)
  - Live bots now resume closed-trade performance memory from the latest saved bot snapshot when the symbol, market, interval, and method still match. That means rolling expectancy/win-rate/profit-factor gates, adaptive filter tightening, loss-streak tracking, and the first post-restart decision continue from prior wins and losses instead of restarting from an empty session.
  - Coinbase live market orders now feed parsed order id, status, filled base size, and executed quote value into the same execution reconciliation path as Binance; when a create response lacks fill evidence, the bot performs a short bounded order-id lookup before deciding whether to update local position state.
  - Fresh-entry gates require the configured open threshold to be finite and non-negative. Negative or non-finite `--open-threshold` / legacy `--threshold` values fail closed instead of being normalized to a zero deadband; a valid zero threshold remains admissible only when the explicit edge sample clears the active headroom, fee, and spike checks.
  - Entries must also clear that deadband with at least `1.5x` edge headroom; forecasts that only barely cross the threshold are held as `HOLD (EDGE_HEADROOM)` instead of opening on a boundary-touching move.
  - Entries are also vetoed when the method-selected absolute edge does not clear the active headroom requirement plus the modeled round-trip cost floor (fees, slippage, spread, and configured fixed/minimum costs), which blocks low-margin trades that only look profitable before costs. The fee floor must be finite and non-negative; negative or non-finite fee inputs and missing or non-finite edge samples fail closed. Backtests and live latest-signal decisions now both apply this fee-buffer gate on the actual fresh-entry path after final entry-size overlays, so fixed/minimum costs cannot be understated by checking a larger pre-overlay size.
  - Fresh-entry sizing now requires the configured maximum and minimum position-size bounds to be finite and non-negative before a new position can open. Negative, `NaN`, or infinite cap/floor evidence fails closed as a no-entry sizing state; valid zero caps and zero floors remain explicit boundaries, and equality at a valid minimum size remains admissible.
  - Backtest JSON now includes cost-attribution accounting under `costAttribution` and `costs.attribution`, with gross and net equity curves, realized fee/slippage/spread/funding totals, total realized cost, and a consistency residual proving `gross - realized costs = net` for the emitted run.
  - Volatility-confidence gate presets now require volatility evidence to be present, finite, and within `[0,2]`; missing, negative, non-finite, or above-range volatility evidence fails closed as exit-only. Provided confidence evidence must be finite and within `[0,1]`; malformed confidence also fails closed as exit-only, while missing confidence remains weak entry-blocking evidence.
  - Conformal prediction calibration now requires a non-empty residual sample where every residual is finite and non-negative. Empty samples or any malformed residual evidence, including negative, `NaN`, or infinite values mixed with otherwise valid residuals, produce an unavailable unbounded interval with no sigma/confidence estimate instead of a tight filtered band. Valid zero residuals remain admissible.
  - Quantile prediction intervals now require finite ordered q10/q50/q90 evidence from a dimension-valid model. Empty or dimension-invalid models, non-finite quantile predictions, and inverted q10/q90 bounds return unavailable quantiles instead of silently sorting or emitting a tight misleading interval. Exact equal q10/q90 bounds remain valid, but produce no sigma estimate.
  - Entries are also suppressed when the method-selected absolute edge exceeds `min(4 * active open-threshold, 0.5)`; exact equality at that cap remains admissible, and non-finite threshold or edge inputs fail closed instead of bypassing the spike veto. This spike veto is separate from the minimum-edge headroom and fee-buffer gates.
  - Backtests and optimizer sweeps now model `--kelly-lite-sizing` with the same `--kelly-lite-fraction`, floor, and cap used by live sizing, so selected configs no longer ignore Kelly-lite exposure changes during historical scoring. When Kelly-lite is enabled, backtest text and JSON output also report realized average exposure versus the same backtest replayed without Kelly-lite sizing; `optimize-equity` and the scorecard can now require Kelly-lite trials to reduce realized exposure materially before they remain eligible, and zero-uncapped-exposure Kelly-lite rows fail that exposure contract instead of passing ratio checks as no-op reductions. `haskell/scripts/run_optimize_equity_top5.sh` exposes the same knobs through `P_KELLY_LITE_SIZING`, `KELLY_LITE_FRACTION_MIN/MAX`, `KELLY_LITE_FLOOR_MIN/MAX`, `KELLY_LITE_CAP_MIN/MAX`, `MIN_KELLY_LITE_EXPOSURE_REDUCTION`, and `MAX_KELLY_LITE_EXPOSURE_RATIO`; the wrapper also passes `LOOKBACK_WINDOW`, filters out intervals that would exceed `TRADER_OPTIMIZER_MAX_POINTS`, and uses `QUALITY_MIN_TRIALS`, `QUALITY_MAX_EPOCHS`, and `QUALITY_MAX_HIDDEN_SIZE` so short quality-mode audit sweeps can keep their requested trial/model budget explicit. Quality mode now also preserves explicit `--bars-min/--bars-max` bounds instead of silently resetting fixed-bar sweeps to auto-sized histories, `NOOPT=1` makes the wrapper build/use matching no-optimization `optimize-equity` and `trader-hs` binaries for fast audit loops, and short fixed-bar audits that produce only `activityCount<N` skips now retry at the deeper `ACTIVITY_RETRY_BARS` counts before giving up. When the deepest history still fails only on activity count, `ACTIVITY_RECOVERY=1` runs one lower-threshold/shorter-hold recovery attempt using the `ACTIVITY_RECOVERY_*` range variables while preserving explicit tight threshold caps under `--quality`. If that recovery still produces only zero-activity neutral latest-signal diagnostics, `NEUTRAL_RECOVERY=1` runs one bounded method-mix retry using the `NEUTRAL_RECOVERY_METHOD_WEIGHT_*` variables, shifting sampling toward edge methods without relaxing eligibility gates; `NEUTRAL_RECOVERY_TIMEOUT_SEC` gives that slower final edge sweep a separate timeout budget that defaults to at least 90 seconds, and `--quality` now preserves explicit zero method weights so that retry can exclude neutral-heavy methods. Failed no-eligible attempts are also written into `summary.json` with status, bar count, trial count, filter-reason counts, and activity diagnostics so audit automation can see whether trials were inactive because of zero trades, sparse trades, or latest-signal HOLD gates.
  - The live `Trader.SignalGates` path now applies the real 24-bar directionality gate instead of the old compatibility shim. Fresh-entry directionality first requires the 24-bar efficiency sample to be finite and within `[0,1]`; missing directionality snapshots plus `NaN`, negative, or above-1 efficiency values are vetoed conservatively instead of being treated as strong-band directional evidence. Entries are now also vetoed as `NON_DIRECTIONAL_CHOP` when 24-bar price efficiency is `<= 0.25`, and as `NON_DIRECTIONAL_MR` when efficiency stays `<= 0.40` while saved HMM regime probabilities are clearly mean-reversion-dominated (using the existing `--regime-bank-hysteresis` gap). In that same weak-directionality review band, `--regime-bank-hysteresis` itself must be finite and non-negative; negative or non-finite values now fail closed as `NON_DIRECTIONAL_MALFORMED` instead of being normalized into a looser MR comparison. In that same weak-directionality review band, fresh long and short entries now share one signed additive-path confirmation rule: the requested side is admissible only when the signed weak-band `zScore` is finite and at least `0.75` (equivalently `zScore >= 0.75` for longs and `zScore <= -0.75` for shorts). Exact equality at the signed boundary remains admissible, while opposite-signed, zero, missing, or non-finite weak-band scores fail closed for the requested side. Saved HMM regime probabilities still fail closed as `NON_DIRECTIONAL_MALFORMED` when any component is missing, non-finite, outside `[0,1]`, or when the three-probability mass is non-positive or drifts by more than `1e-3` from `1`.
  - Directionality efficiency and z-score are derived from the additive per-bar return path, so clean monotonic trend windows remain directional instead of being misclassified as malformed when the compounded endpoint return slightly exceeds the summed simple-return path.
  - `haskell/scripts/review_bot_day.py` now emits additive cutoff observability in both JSON and markdown: interval-aware stale-snapshot diagnostics (`latestSnapshotAgeMs`, per-symbol cutoff freshness rows, `staleSnapshotsAtCutoff`) plus a compact latest pre-cutoff `latestSignal.action` census so zero-trade review windows still show stale snapshots and dominant HOLD reasons.
  - `haskell/scripts/review_bot_day.py` also keeps low-directionality review accounting aligned with the live gate: same-day order flow is partitioned as `entry_or_add` versus `exit_or_flatten`, `nonDirectionalOrderAttempts` counts only entry/add flow, weak-band entry/add reviews use the same signed additive-path zScore rule as live (`zScore >= 0.75` for longs, `zScore <= -0.75` for shorts), and carry-management exits from existing or adopted positions stay in the separate `nonDirectionalExitOrFlattenEvents` / `nonDirectionalUnknownRoleEvents` review buckets.
  - Ops persistence now defaults high-volume Binance REST request audit rows (`binance.request`) off, persists `bot.status` ops snapshots every 5 minutes by default, and supports `TRADER_OPS_DISABLED_KINDS` plus `TRADER_BINANCE_REQUEST_OPS_ENABLED` / `TRADER_BOT_STATUS_LOG_INTERVAL_MS` for production disk-growth control.
  - Fly Postgres disk monitoring is available with `npm run monitor:fly-postgres-disk -- --app tdf-hq-db --warn 75 --critical 85`; set `TRADER_DISK_ALERT_WEBHOOK_URL` to post warning/critical JSON alerts from cron, GitHub Actions, or another scheduler.
  - Live bot auto-start now defaults to a small restart budget: 3 target bots, 0 top-combo bots during the startup phase, and 1 new worker per poll cycle. `/bot/start` launches at most `TRADER_BOT_START_MAX_SYMBOLS` immediately, then queues any remaining requested symbols and starts them one by one after current bots are stable. Queued starts fail the remaining queue after `TRADER_BOT_START_QUEUE_MAX_WAIT_SEC` seconds unless set to `0` for an unbounded wait; transient below-threshold order errors no longer block the queue forever, while halted bots and order errors that reach `--max-order-errors` still block. Live starts skip `TRADER_BOT_DISABLED_SYMBOLS` (default `MATICUSDT`) so delisted/closed symbols do not churn the queue. Tune `TRADER_BOT_TOP_COMBO_BOTS`, `TRADER_BOT_TOP_COMBO_BOTS_STARTUP`, `TRADER_BOT_AUTOSTART_MAX_BOTS`, `TRADER_BOT_AUTOSTART_MAX_STARTS_PER_CYCLE`, `TRADER_BOT_START_MAX_SYMBOLS`, `TRADER_BOT_START_QUEUE_MAX_WAIT_SEC`, and `TRADER_BOT_DISABLED_SYMBOLS` when a deployment has enough memory for wider recovery/adoption.

## Autoloop
- The repo autoloop now treats merged local branches that are still attached to Git worktrees as prune skips instead of blocking the forever runner before any bounded repair cycle starts.
- The forever runner now prunes stale `git worktree` metadata before merged-ref cleanup, and it saves failed dirty-cycle snapshots onto dedicated `autoloop/recovery/*` or `autoloop/checkpoint/*` branches instead of writing those `WIP` rescue commits directly onto `main`.
- The bounded autoloop now includes `hlint app test bench` in its safe verification set and can apply direct `Found:` to `Perhaps:` HLint replacements for editable Haskell files when CI fails on simple HLint-only suggestions.
- The logical-correctness loop now explicitly starts each cycle by auditing the Haskell trading algorithm for more logical and correct behavior, then implements the selected backend fix with tests, formal notes, and local verification where practical.
- The GitHub-hosted autoloop now requires `AUTOLOOP_PUSH_TOKEN`; it no longer falls back to `github.token`, and it no longer skips post-push CI waiting. That keeps Actions polling and failed-log ingestion mandatory after each autoloop push.
- The GitHub-hosted autoloop now installs a pinned prebuilt `fourmolu` release binary instead of compiling `fourmolu` from source on every run, which removes a slow bootstrap step before the bounded loop can start.
